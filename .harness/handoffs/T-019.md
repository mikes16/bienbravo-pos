# Handoff T-019 — Sincronizar schema del API: avisos de datos y ajustes del POS

## Interfaz expuesta
- `Subscription.posDataChanged(slug: String!): PosDataEvent!` disponible en `schema.graphql`; tipos generados en `src/core/graphql/generated/graphql.ts`: `PosDataEvent { kind: PosDataEventKind!; locationSlug: string; occurredAt: string }` y `enum PosDataEventKind { Catalog, Commission, Payment, Register, Settings }`.
- `Query.posSettings: PosSettings!` disponible; tipo generado `PosSettings { posAutoLockIdleSeconds: number; posAutoLockCheckoutSeconds: number }`.
- No se agregó ningún documento `graphql()` en esta tarea. **Actualizado por T-020:** ya existe `POS_DATA_CHANGED` en `src/core/freshness/freshness.queries.ts`, así que `PosDataChangedSubscription`/`PosDataChangedSubscriptionVariables`/`PosDataChangedDocument` están generados y registrados en `gql.ts`. `PosSettings` sigue sin documento: quien lea los ajustes de auto-lock escribe su query con `graphql()` y corre `npm run codegen`.
- De paso, el sync trajo adiciones NO relacionadas ya presentes en el API (no pedidas por esta tarea, solo sincronizadas): campos nuevos en `DashboardLocationRow`/`DashboardTotals` (descuentos, `paidSalesCount`, `ticketPromedioCents`), `PayrollPreviewRow` (split de comisión producto/servicio/propinas + `totalCommissionCents`, `commissionCents` ahora `@deprecated`), y `RegisterSessionAdjustmentKind.REFUND`. Ningún tipo/campo existente fue eliminado.
