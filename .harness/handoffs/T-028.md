## Decisiones tomadas
- `npm run sync-schema` no produjo ningún diff en `schema.graphql`: el API ya traía el bloque completo
  de venta a staff cuando una tarea previa (T-019 o anterior) hizo su propia sincronización — AC-1/AC-2
  ya estaban satisfechos por el estado del repo antes de que esta tarea tocara nada.
- El único diff real que deja esta tarea en `gql.ts`/`graphql.ts` es el documento `Seed` de
  `checkout.repository.test.ts`, generado porque **arreglé** esa query (no porque el schema haya
  cambiado). El fix cae dentro de la tolerancia de "2 extra, solo test/fixture" del protocolo del
  ejecutor: sin él, `npm run codegen` (parte literal de AC-3) no puede pasar de exit 1, sin importar
  qué tan sincronizado esté el schema.
- No se tocó `checkout.repository.ts` ni ningún otro consumidor: el bug estaba únicamente en el query
  ad-hoc de la prueba (nunca viaja a la red — se escribe directo al cache con `cache.writeQuery`), y
  `evictCatalogCache` evict-ea por `fieldName` sin importar los args, así que el fix no cambia lo que
  el test verifica.
