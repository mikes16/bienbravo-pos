# Handoff T-002c — Script lint por ruta: que un check de lint pueda medir un solo feature

## Interfaz expuesta
- Nuevo script npm `lint:path` en `package.json`: `"lint:path": "eslint"`
  (sin el `.` final). Uso: `npm run lint:path -- <ruta> --max-warnings=0`
  para lintear solo esa ruta/archivo, a diferencia de `npm run lint` (=
  `eslint .`, siempre repo-wide, sin cambios).

## Archivos
- Modificado: `package.json`

## Decisiones tomadas
- `lint:path` es literalmente `eslint` sin argumento de ruta fijo: quien lo
  invoca debe pasar la ruta después de `--` (`npm run lint:path -- <ruta>
  --max-warnings=0`). No se le puso un target por defecto para que un check
  de tarea futura pueda acotar a su propio `files[]`.
- No se tocó `eslint.config.js` ni el baseline de errores/warnings
  pre-existentes (documentado en `.github/workflows/ci.yml`); `lint` sigue
  siendo `eslint .` repo-wide y sigue fuera de CI.
- No se agregó documentación en CLAUDE.md/README: no existe una "lista de
  scripts" ni README.md en este repo (solo menciones sueltas en prosa dentro
  de CLAUDE.md), así que la condición "si hay una lista de scripts" de la
  descripción no aplicó.

## Advertencias para dependientes
- `lint:path` no reemplaza a `lint`: para un check de lint con alcance de
  feature en una tarea futura, usar `npm run lint:path -- <ruta>
  --max-warnings=0`, nunca `npm run lint -- <ruta>` (eso sigue expandiendo a
  `eslint . <ruta>` y lintea el repo entero).
