# Handoff T-016c — Caja abierta: los montos esperados con MoneyValue (esqueleto, nunca $0)

## Interfaz expuesta
- `CajaOpenView` cambia de firma:
  ```ts
  interface CajaOpenViewProps {
    session: RegisterSession | null   // null = "no sé" ([D-020])
    todayTransactions: SaleLedgerEntry[]
    fondoCents: number | null         // null = fondo desconocido
    status: MoneyValueStatus          // = useRegister().status, tal cual
    onCerrar: (() => void) | null
  }
  ```
  - Las tres cifras del corte (Efectivo esperado / Tarjeta / Stripe) se pintan con
    `MoneyValue` `size="S"` (36 px; `M` son 56 px y desborda la columna de la tarjeta),
    `label` = el mismo rótulo visible ([D-005], [D-006]). `cents = session?.expected*Cents ?? null`.
  - `session === null` → las tres tarjetas son esqueleto **y** la línea "Desde … · fondo …"
    se reduce a su propio esqueleto (`SkeletonText` dentro de un span de 18ch, `aria-hidden`):
    no se inventa hora de apertura ni fondo.
  - El banner "Caja abierta", el ledger "Ventas de hoy" y el CTA de cerrar caja no cambiaron.
    El total del ledger es `null` sin sesión y entonces el header dice sólo "N ventas".
- `CajaPage` pasa `status={status}` de `useRegister`. El early-return de esqueleto de página
  sigue siendo sólo para `status === 'loading'` (sin dato alguno), así que hoy esta vista
  recibe siempre una sesión real; el caso `null` es defensa propia de la vista.
- Tests: las cifras ya NO se encuentran con `getByText('$1,840')` (MoneyValue parte `$` y el
  número en spans distintos). Se consultan por nombre accesible:
  `screen.getByRole('group', { name: 'Efectivo esperado' })` + `toHaveTextContent('$1,840')`.
  `aria-busy="true"` sólo en `loading`/`updating`; en `fresh` el atributo no existe ([D-007]).

## Decisiones tomadas
- `size="S"` y no `M`: los numerales suben de 22 px a 36 px (el escalón de numeral más chico
  del POS); 56 px no cabe en una rejilla de 3 columnas en la iPad. Si alguien quiere el peso
  visual de `M`, primero hay que romper la rejilla en 3 filas, no achicar el token.
- La tarjeta se extrajo a un `ExpectedAmountCard` local (no exportado) para no repetir tres
  veces rótulo + numeral y para que el contrato "rótulo visible == `label` accesible" sea
  imposible de romper en una de las tres.
- `fondoCents` pasa a `number | null` en vez de seguir siendo obligatorio: con `session === null`
  el fondo tampoco se sabe, y un `0` de relleno ahí es exactamente el $0 falso que prohíbe la
  spec § 3.1b.
- El `as any` del fixture del ledger en el test se eliminó tipando `SaleLedgerEntry[]`: los dos
  warnings de `no-explicit-any` que arrastraba el archivo desaparecieron.

## Advertencias para dependientes
- **`fondo` sigue con `formatMoney` directo** (caption de 11 px dentro del banner, no un
  numeral): es dinero del servidor y, cuando alguien necesite que respete el status, migrarlo
  es un `MoneyValue size="S"` más un rediseño de esa línea. Queda como deuda consciente, fuera
  del alcance de esta tarea (AC-2 sólo prohíbe `formatMoney(session.…)`).
- No vuelvas a leer `session` sin `?.` en esta vista: el typecheck te obliga al `?.`, pero el
  bug real es tratar `null` como "la caja no tiene movimientos" ([D-020]).
- **T-016d (espera/bloqueo del corte)**: `CloseCajaWizard` no se tocó aquí; sigue como lo dejó
  T-044 (devuelve `null` mientras no hay sesión).
- `steps/ConfirmDigitalStep.tsx` conserva su error de lint pre-existente y `CloseCajaWizard.tsx:46`
  su warning `react-hooks/set-state-in-effect`: por eso el check de lint se acota a los archivos
  tocados. `npx eslint` sobre los tres archivos de esta tarea sale limpio (0 problemas).
