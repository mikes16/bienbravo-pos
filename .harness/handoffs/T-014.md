# Handoff T-014 — Hoy: las comisiones vienen siempre de la red, con esqueleto y canal único

## Interfaz expuesta
- `HoyViewModelInput.commission` / `HoyViewModel.commission` (deriveHoyViewModel.ts) **cambió**:
  ```ts
  { amountCents: number | null; serviceCount: number | null; status: MoneyValueStatus }
  // salida: lo mismo + projectedCents: number | null   (se fue `loading: boolean`)
  ```
  `null` es "no sé" y jamás se rellena con 0; `status` (de `@/shared/pos-ui`) lo decide quien
  carga el dato. El derive sólo lo transporta: cero lógica de dinero en el componente.
- `HoyView` acepta `onRetryCommission?: () => void` (botón "Reintentar" del estado `error`).
  La cifra se consulta en tests con `getByRole('group', { name: 'Comisiones hoy' })`
  + `toHaveTextContent('$660')`; `getByText('$660')` ya no encuentra nada ([D-006], MoneyValue `size="S"`).
- `HoyPage` **exige `FreshnessContext` arriba**: registra dos cargas con `useLiveRefresh` —
  comisiones en `['sales']`, lista (citas + fila + reloj + caja) en `['walkins', 'appointments']`.
  Sin provider, `useFreshness` lanza (en la app ya está montado desde T-011).

## Decisiones tomadas
- **Un `refetch` monolítico se partió en dos cargas independientes**: `loadCommission` (DINERO,
  `network-only` sin alternativa) y `loadBoard` (VIVO sin dinero, repos con `force: true` + caja
  `network-only`). Por eso un aviso de `sales` NO recarga la fila y uno de `walkins` no toca el dinero.
- **El view-model se deriva en render (`useMemo`) desde dos estados** (`board`, `earnings`) en vez de
  guardarse en un `setVm` dentro del fetch: así el dinero puede estar en esqueleto mientras la lista
  ya se ve, sin duplicar el VM ni sincronizar dos copias.
- **`serviceCount` es `null` mientras no responden las comisiones** (las ventas directas salen de
  `perSale`): el pie dice "Cargando…" y nunca "0 servicios" junto a una cifra que aún es esqueleto.
- **`staffDayEarnings` sin dato = fallo**, no `$0`: se lanza error para caer a `error`/`offline`.
- **`offline` vs `error` se decide con `connection` del canal** (`useFreshness`), no con el tipo de
  excepción: si el socket está caído es "Sin conexión"; si no, "No se pudo cargar" + Reintentar.
- **`loadBoard` rechaza si alguna de sus 4 lecturas falló** (aunque pinte lo que sí llegó): así la
  hora de "Actualizado HH:MM" del canal no se mueve con datos incompletos (contrato de T-007).
