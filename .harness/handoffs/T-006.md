# Handoff T-006 — MoneyValue: una cifra de dinero nunca se muestra vieja ni como $0 falso

## Interfaz expuesta
`import { MoneyValue, type MoneyValueStatus } from '@/shared/pos-ui'`

```ts
type MoneyValueStatus = 'loading' | 'fresh' | 'updating' | 'offline' | 'error'

interface MoneyValueProps {
  status: MoneyValueStatus
  cents: number | null   // null = "no sé" → esqueleto, nunca $0
  label: string          // etiqueta accesible obligatoria, ej. "Total del día"
  size?: 'S' | 'M' | 'L' // mismo escalón que MoneyDisplay (default 'M')
  onRetry?: () => void   // si viene, el estado 'error' pinta "Reintentar"
  className?: string
}
```

Contrato de render (spec 2026-09-18 § 3.1b):
- `loading` → esqueleto del alto del numeral (`SkeletonText` dentro de una caja con el
  mismo `font-size`/`line-height` que MoneyDisplay): sin salto de layout, sin dígitos, sin `$`.
- `fresh` → la cifra vía `MoneyDisplay`. `cents={0}` con `fresh` es un 0 REAL y se pinta.
- `updating` → cifra con `opacity-40` + punto indicador; **a los 1000 ms exactos** pasa a esqueleto.
- `offline` → `—` + "Sin conexión". `error` → `—` + "No se pudo cargar" (+ botón si hay `onRetry`).
- Raíz: `role="group"` + `aria-label={label}`; `aria-busy="true"` solo en `loading` y `updating`
  (en los demás el atributo se omite, no se pone en "false").

Consulta en tests: `screen.getByRole('group', { name: <label> })`.

## Decisiones tomadas
- `label` es **obligatorio**: toda cifra de dinero en pantalla queda anunciada y consultable por
  nombre accesible. Los call sites deben pasar el rótulo que ya muestran arriba del numeral.
- El grace de 1 s es la constante `UPDATING_GRACE_MS` del módulo, no una prop: el umbral lo fija
  la spec y no debe variar por pantalla.
- `fresh`/`updating` con `cents === null` caen a esqueleto (defensa: un dato ausente jamás se
  convierte en $0).
- El reloj de 1 s se reinicia con el patrón de "ajustar estado en render" (comparar el status
  renderizado anterior), no con `setState` dentro del efecto: evita el warning de
  `react-hooks/set-state-in-effect` y un render extra.
- El botón "Reintentar" es `TouchButton size="min"` con `style` de 44×44 px: el escalón
  `--pos-touch-min` son 40 px y la tarea exige ≥ 44 px. No se tocó el token ni el design system.

## Advertencias para dependientes
- No pintes dinero del servidor con `MoneyDisplay` directo en pantallas nuevas: `MoneyDisplay` es
  el formateador; `MoneyValue` es el componente con estados. Mapea el estado de tu carga
  (loading/fresh/updating/offline/error) y pásalo, nunca conserves la cifra anterior en estado local.
- `updating` solo es legítimo cuando la cifra mostrada **acaba de venir del servidor** y ya se pidió
  la nueva (evento de otra iPad). Si la validez es desconocida, es `loading`.
- El ancho del esqueleto es `4.5ch` del numeral (aprox. "$1,234"). Si una pantalla muestra cifras
  mucho más largas y el salto se nota, se parametriza el ancho ahí — no se hardcodea por fuera.
- El componente no consulta ni conoce repositorios: el estado lo decide quien carga el dato
  (`useLiveRefresh`/`FreshnessProvider` cuando existan).
